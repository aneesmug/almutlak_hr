🔄 WORKFLOW:

1. Employee clicks "Apply for Loan"
2. Selects loan type and amount
3. Enters installments (if applicable)
4. Clicks "Submit Application"
5. AJAX sends: emp_id, loan_amount, loan_type, installments
6. Backend apply_for_loan() executes:
   → Check 1: Is emp_id in database? (existing check)
   → Check 2: Does employee have pending/awaiting loan? [NEW]
      YES: Return pending_request response with approval chain
      NO: Continue with normal processing
7. Frontend receives response:
   → If type='pending_request': Show "Cannot apply now" modal
   → Else: Show normal success/error message

📊 DATABASE QUERIES:

Query 1: Check for pending loans
─────────────────────────────────
SELECT id, inv_no, loan_type, loan_amount, status, created_at 
FROM emp_loan 
WHERE emp_id = ? AND status IN ('pending', 'awaiting')
LIMIT 1

Uses prepared statement with bind_param("s", $emp_id)

Query 2: Get approval chain
──────────────────────────
SELECT ra.approval_level, ra.status, 
       COALESCE(e.name, al.fullname, al.username) as approver_name,
       ra.action_date
FROM request_approvers ra
LEFT JOIN employees e ON ra.approver_id = e.emp_id
LEFT JOIN admin_login al ON ra.approver_id = al.id_iqama
WHERE ra.request_inv_no = ? AND ra.request_type_id = 2
ORDER BY ra.approval_level ASC

Uses prepared statement with bind_param("s", $inv_no)

Query 3: Get current approver at pending level
──────────────────────────────────────────────
SELECT COALESCE(e.name, al.fullname, al.username) as approver_name
FROM request_approvers ra
LEFT JOIN employees e ON ra.approver_id = e.emp_id
LEFT JOIN admin_login al ON ra.approver_id = al.id_iqama
WHERE ra.request_inv_no = ? AND ra.request_type_id = 2 AND ra.approval_level = ?

Uses prepared statement with bind_param("si", $inv_no, $pending_level)
